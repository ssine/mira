# 对话完成通知

在 Mira 的设备页或对话侧边栏菜单选择「开启完成通知」，允许系统通知即可。
开关只作用于当前设备；每轮根对话成功完成后会显示「对话已完成」和对话标题，点击回到对应对话。
通知适用于 Codex 对话。子任务、取消和失败不发送完成通知。

需要 HTTPS、支持 Web Push 的浏览器，以及手机与浏览器推送服务之间可用的网络。
iPhone/iPad 需要 iOS/iPadOS 16.4 或更新版本，先通过分享菜单将 Mira 添加到主屏幕，
再从主屏幕打开并开启通知。Android 可使用支持 Web Push 的 Chrome 等浏览器。
系统通知权限、省电/勿扰设置和浏览器推送服务会影响到达时间；这不是短信，也不依赖 Mira Android Node。
页面关闭、锁屏或切换应用后，Server 仍可发送，实际到达需要在目标手机上验收。

选择「关闭完成通知」可撤销本机订阅。退出登录、登录过期或管理员重置密码后，
Server 停止向该登录会话的设备发送；已交给浏览器推送服务的消息可能仍会到达。
重新登录后，仅在本机先前保留开启偏好且通知权限仍有效时恢复订阅。
浏览器删除订阅或 Server 更换密钥后，需重新开启通知。

## 实现与边界

- 标准 Web Push：浏览器 Push API、Service Worker、VAPID 和 aes128gcm 加密。
  Server 首次开启时生成 VAPID 密钥并存入 PostgreSQL；升级和重启沿用密钥。
  备份数据库时必须保留密钥和订阅。API 仅返回公钥，日志不记录订阅地址、认证材料或消息内容。
- schema 32 添加独立的密钥、订阅和发送队列表，兼容上一版 Server 回滚。
  开启订阅不回填旧记录。队列与完成事件在同一数据库事务中提交，不依赖 WebSocket 或浏览器在线。
  Codex 只处理已有代际的追加写入，支持 v1 snapshot 和 v2 delta，包括上传后追加；
  导入、fork 复制、替换代际和重建投影不重发历史完成提醒。
- 推送订阅绑定管理员登录会话，写入需要 CSRF。最多 32 个有效设备订阅；
  一个后台 worker 串行发送，连接有超时，队列有效期一天，临时错误最多重试六次。
  404/410 清除失效订阅；关闭订阅会删除其队列。发送前检查会话、对话和代际仍然有效。
- 每个订阅、运行时、对话代际和 turn 只入队一次。推送服务接收成功后若 Server 在保存发送结果前退出，
  可能重发；稳定的 push topic 和 notification tag 合并仍在途或仍显示的同一轮通知，不承诺 exactly-once 到达。
  已处理队列保留至一天到期，不是权威会话历史，也不会触发工具重放。
- 通知只包含标题和对话链接，不包含回复正文或工具输出。点击时优先唤回已打开的 PWA，
  在应用内切换对话并保留文字及附件草稿；正在提交或操作对话的窗口不会被切走。
  没有可复用的 PWA 时，复用同一对话的浏览器窗口或请求新窗口。链接严格限制为本站对话路由。
  PWA 已完全关闭时，是否以独立应用打开由浏览器决定；Android Edge 可能打开普通标签页，
  Web API 无法强制冷启动独立 PWA。Chrome 的已安装 Web App 通常能更好地接管此类链接，仍需手机实测。
- 推送地址只允许 HTTPS 443；发送时解析并连接公网 IP，拒绝重定向，防止订阅地址访问内网。

验证：`node --test tests/pwa_notifications_test.mjs`；
`MIRA_HISTORY_UPLOAD_TEST_DATABASE_URL=... go -C node test ./internal/miraserver -run '^TestPush'`。
数据库测试用模拟推送服务验证加密请求、重启消费、重试、去重和撤销；不等同于真实手机锁屏送达测试。
